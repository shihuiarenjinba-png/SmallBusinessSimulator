## 保護条件
- 全て独立した feature ブランチ。既存 main / 既存 Release / Partner Center の申請には変更しない
- 資料・ライセンス不明の有料素材、外部 API、サーバー、追加課金なし

## コード担当がWindows上で実施すること

それぞれ既存の未コミット変更を確認し、保護した新規作業フォルダで確認する。
```powershell
git status --short
git fetch origin
git switch --detach origin/feature/ui-calculation-consistency-20261019
npm ci
npm test
```
※ 上は SmallBusinessSimulator 用の例。ほかの作品はこの資料の対象ブランチ名に置き換える。
※ `npm ci` は各リポジトリの lockfile が存在する場合のみ。ない場合は勝手に既存の依存関係を消去せず、まず環境を点検する。
※ ワークフロー実行の冒頭ステップに達しない CI 失敗は、Node テストの不合格として数えない。原因をログや Actions 画面で記録する。

### 手動の必須チェック
1. 各タブをクリックし、表示される背景・操作項目・説明が一致するか（練習中に走者なし、倉庫に来客なし）
2. 1280×720 / 1920×1080、表示倍率100% / 125% / 150%、ウィンドウ最小サイズで文字・ボタンの欠けがないか
3. 小規模経営で売り切れ後に翌日入庫→販売。賞味期限前自動20/50%値引き。入庫ゼロの日にはベルト非表示。7日進行で仕入/借入が二重にならないか
4. 中古品店で倉庫の1ページと2ページを往復。価格・陳列・修理選択を維持。一括値引き対象がページ外にも反映。販売前に値引き額を確認
5. 工場で検査率・人員を変えてから実行。出荷後の結果パネルに実数値が表示。未実行の見込みと実績を混同しない
6. 深夜監査室で証拠なし/ありの報告判断、キャンセル時は結果画面に進まない。次の案件が表示される
7. 引継ぎ室では人物会話・ノート切替、既存シナリオと旧セーブ復元、証拠の正解をUIが自動で教えないこと
8. EKIDENで1〜12週、合同練習費・配分、レース開始/区間進行/終了/次年度。練習タブでは選手の走行演出を表示しない
9. 流動資産ゲームのポートフォリオ・売買・借入・履歴を順に確認。表示数値と約定履歴を照合
10. 各作品で保存→完全終了→再起動→再読込、長期試遊、インストール/アンインストール、MSIX/WACK PASS
